# 新同学上手指南

本文面向第一次接触本仓库的同学。读完后你应该能：

1. 说清后端 Maven 工程与前端工程各目录的职责；
2. 在本地把后端跑起来、把前端页面打开；
3. 在页面上算出一条示例路线（解放碑 → 磁器口古镇，约 **13.48 km**）。

> 项目全称：重庆旅游线路规划系统。技术栈：React + TypeScript（Vite）/ Java 17 + Maven + 内置 HTTP Server + Hibernate / PostgreSQL 15。

## 2. 后端 Maven 目录：backend/

采用标准 Maven 布局，包根路径 `com.cqu`：

```
backend/
├── pom.xml                                    # Maven 构建文件（依赖、打包配置）
├── settings.xml                               # 国内 Maven 镜像（阿里云），供 Docker 构建使用
├── Dockerfile                                 # 后端镜像构建脚本（多阶段：maven 编译 → jre 运行）
└── src/
    ├── main/
    │   ├── java/com/cqu/
    │   │   ├── Main.java                      # ★ 启动入口：main()，初始化 DB/图/HTTP 服务
    │   │   ├── model/                         # ★ 数据模型（实体/DTO）
    │   │   │   ├── Node.java                  #   景点节点（JPA 实体，映射 nodes 表）
    │   │   │   ├── Edge.java                  #   边（起终点 ID + 可选距离，仅内存使用）
    │   │   │   └── PathResult.java            #   路径规划结果（起终点/总距离/途经节点/分段距离）
    │   │   ├── service/                       # ★ 业务逻辑层
    │   │   │   ├── Db.java                    #   Hibernate EntityManagerFactory 初始化
    │   │   │   ├── NodeRepository.java        #   节点增查（JPA）
    │   │   │   ├── DataLoader.java            #   从 classpath 读取 nodes.csv / edges.csv
    │   │   │   ├── GraphService.java          #   建图 + Dijkstra 最短路径（核心算法）
    │   │   │   └── GeoUtils.java              #   Haversine 球面距离工具
    │   │   └── handler/
    │   │       └── RequestHandler.java        # ★ Controller 角色：HTTP 路由处理
    │   │                                      #   （/api/health、/api/nodes、/api/path，含 CORS）
    │   └── resources/
    │       ├── META-INF/persistence.xml       # JPA/Hibernate 持久化单元配置（名称 cq-travel）
    │       ├── nodes.csv                      # ★ 测试数据：景点节点（12 条，必需）
    │       └── edges.csv                      # ★ 测试数据：边（18 条，可选；缺失则按经纬度自动构图）
    └── test/
        └── java/com/cqu/service/
            └── GraphServiceTest.java          # JUnit 5 单元测试（最短路径，无需数据库）
```

要点速查：

| 问的内容 | 位置 |
| --- | --- |
| Main（程序入口） | `backend/src/main/java/com/cqu/Main.java` |
| model | `backend/src/main/java/com/cqu/model/`（`Node` / `Edge` / `PathResult`） |
| service | `backend/src/main/java/com/cqu/service/`（图算法、数据加载、DB、仓储） |
| controller | 本项目没有 Spring，没有 `controller` 包；由 `handler/RequestHandler.java` 承担，路由在 `Main.java` 中注册 |
| 静态资源 / 测试数据 | `backend/src/main/resources/`（`nodes.csv`、`edges.csv`、`META-INF/persistence.xml`） |
| 测试代码 | `backend/src/test/java/com/cqu/service/GraphServiceTest.java` |

后端**没有独立的 `.sh` 启动脚本**，启动入口有三种（等价）：

- 容器方式：仓库根目录的 `docker-compose.yml` + `backend/Dockerfile`；
- Maven 方式：`mvn package` 后运行 `target/backend-1.0.0-jar-with-dependencies.jar`（`pom.xml` 已配置主类 `com.cqu.Main`）；
- IDE 方式：直接运行 `com.cqu.Main` 的 `main()`。

### CSV 数据格式（测试数据长什么样）

- `nodes.csv`（必需）：表头 `id,name,lat,lng,type,desc`，例如 `JIEFANGBEI,解放碑,29.56301,106.57577,地标,...`。
- `edges.csv`（可选）：表头至少 `from,to`，本仓库未提供距离列，边权由两端经纬度用 Haversine 公式自动计算（米）。
- 首次启动时若 `nodes` 表为空，后端会自动把 `nodes.csv` 导入 PostgreSQL（seed 逻辑在 `Main.java`）。

## 4. 启动方式 A：Docker Compose 一键启动（推荐，最省事）

前置条件：本机装有 Docker Desktop / Docker Engine（会一并拉起 PostgreSQL、后端、前端）。

```bash
# 在仓库根目录
docker compose up -d --build
```

启动后：

- 前端：http://localhost:3514
- 后端健康检查：http://localhost:8514/api/health （应返回 `{"status":"ok",...}`）
- 节点接口：http://localhost:8514/api/nodes
- PostgreSQL：localhost:5514（库 `cq_travel`，用户/密码 `cq/cq`）

停止：`docker compose down`（想连数据一起清掉：`docker compose down -v`）。

## 5. 启动方式 B：本地分别启动前后端（适合日常开发调试）

### 5.1 先起数据库

只需 PostgreSQL，最简单的办法是只启动 compose 里的 db 服务：

```bash
docker compose up -d db
```

它在宿主机暴露 **5514** 端口；本地后端连库时用 `DB_PORT=5514`。

### 5.2 启动后端

前置条件：JDK 17（`pom.xml` source level 为 11，JDK 11/17 均可，Docker 镜像用 17）、Maven 3.9+。

```bash
cd backend

# 国内网络可加 -s settings.xml 使用阿里云 Maven 镜像
mvn package

# 用 5514 端口的容器数据库启动；端口设 8514 是为了匹配前端 Vite 代理
PORT=8514 \
DB_HOST=localhost DB_PORT=5514 DB_NAME=cq_travel DB_USER=cq DB_PASSWORD=cq \
java -jar target/backend-1.0.0-jar-with-dependencies.jar
```

Windows PowerShell 写法：

```powershell
$env:PORT="8514"; $env:DB_HOST="localhost"; $env:DB_PORT="5514"
$env:DB_NAME="cq_travel"; $env:DB_USER="cq"; $env:DB_PASSWORD="cq"
java -jar target/backend-1.0.0-jar-with-dependencies.jar
```

看到日志 `Backend started on port 8514` 即成功。验证：

```bash
curl http://localhost:8514/api/health
curl http://localhost:8514/api/nodes
```

后端可用的环境变量（均有默认值）：`PORT`（默认 8080）、`DB_HOST/PORT/NAME/USER/PASSWORD`（默认 localhost:5432、cq_travel、cq/cq）、`GRAPH_K`（默认 6）、`GRAPH_MAX_DISTANCE_METERS`（默认 15000）。

跑后端单元测试（不需要数据库）：

```bash
cd backend
mvn test
```

### 5.3 启动前端

前置条件：Node.js 20+、pnpm 10（没有 pnpm 可用 `corepack enable` 或 `npm i -g pnpm@10.17.1` 安装）。

```bash
cd frontend
pnpm install
pnpm dev
```

打开 Vite 输出的地址（默认 **http://localhost:5173/**）。开发模式下 `/api/*` 会被代理到 `http://localhost:8514`（见 `vite.config.ts`），所以前端必须与 5.2 节中 `PORT=8514` 的后端配合使用。

## 6. 算出一条示例路线（验收操作）

以 **起点：解放碑（JIEFANGBEI）→ 终点：磁器口古镇（CIFENGLOU）** 为例。

### 6.1 页面操作（两种启动方式通用）

1. 打开前端页面（Docker 方式 http://localhost:3514，本地 dev 方式 http://localhost:5173）；
2. 左侧「起点」下拉搜索并选择 **解放碑**，「终点」选择 **磁器口古镇**；
3. 点击「开始规划」；
4. 左侧结果列表与右侧地图折线应展示：

   | 序号 | 途经节点 | 与上一点距离 |
   | --- | --- | --- |
   | 1 | 解放碑 | — |
   | 2 | 三峡博物馆 | ≈ 2385 m |
   | 3 | 人民大礼堂 | ≈ 206 m |
   | 4 | 鹅岭公园 | ≈ 4414 m |
   | 5 | 磁器口古镇 | ≈ 6477 m |

   **总距离约 13.48 km。**

### 6.2 或直接用接口验证

```bash
curl "http://localhost:8514/api/path?from=JIEFANGBEI&to=CIFENGLOU"
```

返回 JSON 中：

- `totalDistanceMeters` ≈ `13482`；
- `pathNodeIds` 为 `["JIEFANGBEI","THREE_GORGES_MUSEUM","PEOPLE_GREAT_HALL","ELINGPARK","CIFENGLOU"]`。

路径算法是 Dijkstra（`GraphService.shortestPath`），边权为 `edges.csv` 给定的边、按经纬度算出的球面距离。

## 7. 常见问题

- **前端报「加载节点失败」**：后端没启动，或本地后端没跑在 8514 端口（Vite 代理写死指向 8514）。先用 `curl http://localhost:8514/api/health` 确认。
- **后端启动卡在连数据库**：确认 `docker compose up -d db` 已就绪（`docker compose ps` 中 db 为 healthy），且 `DB_PORT` 用的是宿主机映射端口 5514，不是容器内端口 5432。
- **改了 `nodes.csv` 页面没变化**：seed 只在表为空时执行。清库重灌：`docker compose down -v` 后重新 `docker compose up -d --build`。
- **想改边/节点数据**：编辑 `backend/src/main/resources/` 下的 CSV 后重启后端（容器方式需重新 build backend 镜像）。
- **8514 / 3514 / 5514 端口被占用**：在 `docker-compose.yml` 调整左侧宿主机端口映射即可。
