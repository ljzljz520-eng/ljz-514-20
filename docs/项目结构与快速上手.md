# 项目结构与快速上手（新同学必读）

读完本文并按步骤操作，你可以：**启动后端 → 打开前端 → 算出一条示例路线**。


## 2. 后端 Maven 目录（`backend/`）

标准 Maven 布局：`pom.xml` 在根，源码在 `src/main/java`，资源在 `src/main/resources`，测试在 `src/test/java`。

```
backend/
├── pom.xml                          # Maven 配置：依赖、插件、主类
├── settings.xml                     # Maven 阿里云镜像（构建加速，配合 -s 参数使用）
├── Dockerfile                       # 后端镜像构建脚本（Maven 构建 → JRE 运行）
└── src/
    ├── main/
    │   ├── java/com/cqu/
    │   │   ├── Main.java            # ★ 程序入口（main 方法）
    │   │   ├── handler/
    │   │   │   └── RequestHandler.java   # ★ 控制层（相当于 controller）
    │   │   ├── model/               # ★ 数据模型
    │   │   │   ├── Node.java        #   景点节点（JPA 实体，对应表 nodes）
    │   │   │   ├── Edge.java        #   边（起终点 ID + 可选距离权重）
    │   │   │   └── PathResult.java  #   路径规划结果（返回值结构）
    │   │   └── service/             # ★ 业务逻辑层
    │   │       ├── GraphService.java    #   建图 + Dijkstra 最短路
    │   │       ├── DataLoader.java      #   读取 nodes.csv / edges.csv
    │   │       ├── NodeRepository.java  #   节点表的增查（JPA）
    │   │       ├── Db.java              #   数据库连接（读环境变量）
    │   │       └── GeoUtils.java        #   经纬度球面距离（Haversine）
    │   └── resources/               # ★ 静态资源 / 测试数据（打进 jar）
    │       ├── nodes.csv            #   景点节点数据（必需，12 个重庆景点）
    │       ├── edges.csv            #   边数据（可选，18 条边）
    │       └── META-INF/
    │           └── persistence.xml  #   JPA 持久化单元配置
    └── test/
        └── java/com/cqu/service/
            └── GraphServiceTest.java    # 单元测试（JUnit 5，纯内存、无需数据库）
```

### 2.1 入口 Main 做了什么

`backend/src/main/java/com/cqu/Main.java` 启动流程：

1. 读环境变量 `PORT`（默认 `8080`）；
2. 连接 PostgreSQL（`Db` / `NodeRepository`），若节点表为空则把 `nodes.csv` 导入数据库（seed）；
3. 从数据库读全部节点 + 从 `edges.csv` 读边，交给 `GraphService` 建图；
4. 用 JDK 内置 `HttpServer` 注册三个接口并启动：

| 接口 | 说明 |
| --- | --- |
| `GET /api/health` | 健康检查，返回 `{"status":"ok",...}` |
| `GET /api/nodes` | 返回全部景点节点（JSON 数组） |
| `GET /api/path?from=<起点ID>&to=<终点ID>` | 返回最短路径（Dijkstra） |

> 说明：本项目**没有引入 Spring**，控制层（controller 角色）由
> `handler/RequestHandler.java` + JDK 内置 `com.sun.net.httpserver.HttpServer` 承担，
> 跨域（CORS）与 JSON 序列化也在该类中处理。

### 2.2 后端环境变量（`service/Db.java`、`Main.java` 中读取）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | 后端监听端口 |
| `DB_HOST` / `DB_PORT` | `localhost` / `5432` | 数据库地址 |
| `DB_NAME` / `DB_USER` / `DB_PASSWORD` | `cq_travel` / `cq` / `cq` | 数据库库名与账号 |
| `GRAPH_K` | `6` | 无边数据自动构图时，每点连接的近邻数 |
| `GRAPH_MAX_DISTANCE_METERS` | `15000` | 自动构图的最大边长（米） |

```
├── public/

    ├── components/
    │   ├── ControlPanel.tsx  # 起终点选择、“开始规划”按钮、结果展示
    │   ├── MapContainer.tsx  # Leaflet 地图：节点标注 + 路线折线
    │   ├── Empty.tsx         # 空状态组件
    │   └── ErrorBoundary.tsx # 渲染异常兜底
    ├── stores/
    │   └── useTravelStore.ts # zustand 全局状态；调用 /api/nodes 与 /api/path
    ├── hooks/useTheme.ts     # 主题 Hook
```

前端访问后端的约定（见 `src/stores/useTravelStore.ts`）：

- API 基础路径 = 环境变量 `VITE_API_BASE`，缺省为 `/api`；
- 开发模式（`pnpm dev`）：由 `vite.config.ts` 把 `/api` 代理到 `http://localhost:8514`；
- 生产模式（Docker）：由 `nginx.conf` 把 `/api` 反代到 `backend:8080`。

## 4. 启动脚本都在哪

| 启动方式 | 文件 / 命令 | 说明 |
| --- | --- | --- |
| 一键启动（推荐） | 根目录 `docker-compose.yml` → `docker compose up -d --build` | 同时拉起 db、backend、frontend |
| 后端镜像构建 | `backend/Dockerfile` | Maven 打包出 `*-jar-with-dependencies.jar`，用 JRE 17 运行 |
| 后端本地启动 | `mvn -s settings.xml package` 后 `java -jar target/backend-1.0.0-jar-with-dependencies.jar` | 主类已在 `pom.xml` 中声明为 `com.cqu.Main` |
| 后端测试 | `mvn -s settings.xml test` | 运行 `GraphServiceTest`（不需要数据库） |
| 前端镜像构建 | `frontend/Dockerfile` | `pnpm build` 产物交给 nginx |
| 前端本地启动 | `pnpm install` 后 `pnpm dev` | Vite 开发服务器，默认 http://localhost:5173 |

## 5. 测试数据在哪

| 文件 | 作用 | 格式 |
| --- | --- | --- |
| `backend/src/main/resources/nodes.csv` | 景点节点（**必需**），当前 12 个重庆景点 | 表头 `id,name,lat,lng,type,desc`，前四列必填 |
| `backend/src/main/resources/edges.csv` | 边数据（**可选**），当前 18 条边 | 表头至少 `from,to`；可选第三列 `distance_meters` 作为权重 |

数据流转：

1. 后端**首次启动**时，若数据库节点表为空，自动把 `nodes.csv` 导入 PostgreSQL（之后以数据库为准）；
2. `edges.csv` 每次启动时读取：存在且非空 → 按边建图（无权重列时按两点球面距离计权）；缺失或为空 → 按 `GRAPH_K` / `GRAPH_MAX_DISTANCE_METERS` 自动连接近邻兜底构图；
3. 修改 CSV 后需重新构建并重启后端才生效（Docker：`docker compose up -d --build backend`）。

## 6. 快速上手：启动后端 → 打开前端 → 算一条路线

### 方式 A：Docker 一键启动（推荐，最省事）

前置条件：已安装并启动 Docker（含 docker compose）。

```bash
# 1. 在仓库根目录执行
docker compose up -d --build

# 2. 验证后端已启动（应返回 {"status":"ok",...}）
curl http://localhost:8514/api/health

# 3. 验证节点数据（应返回 12 个景点的 JSON 数组）
curl http://localhost:8514/api/nodes
```

### 方式 B：本地分别启动（适合开发调试）

前置条件：JDK 17+、Maven 3.6+、Node 20+ 与 pnpm（可用 `corepack enable` 启用）、Docker（仅用于起数据库）。

```bash
# 1. 起数据库（宿主机 5514 端口）
docker compose up -d db

# 2. 起后端（监听 8514，与前端 vite 代理约定一致）
cd backend
mvn -s settings.xml package          # 首次会下载依赖，稍慢
DB_PORT=5514 PORT=8514 java -jar target/backend-1.0.0-jar-with-dependencies.jar
#    看到 “Backend started on port 8514” 即成功；另开一个终端继续

# 3. 起前端（另开终端）
cd frontend
pnpm install                          # 或 corepack pnpm install
pnpm dev                              # 打开 http://localhost:5173
```

> 没有 pnpm 时执行 `corepack enable` 即可（Node 20 自带 corepack）。
> 若后端用默认 8080 端口启动，请改 `frontend/vite.config.ts` 的代理目标，
> 或以 `VITE_API_BASE=http://localhost:8080/api pnpm dev` 启动前端。

### 打开前端，算一条示例路线

1. 浏览器打开前端地址（Docker 方式：<http://localhost:3514>；本地 dev：<http://localhost:5173>）；
2. 左侧控制面板中：
   - **起点** 选择「解放碑」；
   - **终点** 选择「磁器口古镇」；
3. 点击 **「开始规划」**；
4. 预期结果（基于当前 `nodes.csv` + `edges.csv` 实测）：
   - 总里程 **约 13.48 km**；
   - 路径：**解放碑 → 三峡博物馆 → 人民大礼堂 → 鹅岭公园 → 磁器口古镇**；
   - 右侧地图会画出这条蓝色路线并自动缩放到合适范围。

## 7. 常见问题

| 现象 | 排查 |
| --- | --- |
| 前端提示「加载节点失败」 | 后端没启动或端口不对：先 `curl http://localhost:8514/api/health` 确认 |
| 后端启动报数据库连接失败 | 数据库未启动：`docker compose up -d db`；本地直连时注意 `DB_PORT` 应为 `5514`（compose 映射端口） |
| `mvn` 下载依赖慢 | 已提供 `backend/settings.xml`（阿里云镜像），记得加 `-s settings.xml` |
| 改了 CSV 没生效 | CSV 打进 jar/镜像，需重新构建：`docker compose up -d --build backend`；若节点表已有数据，需清空表才会重新 seed |
| 端口被占用 | 修改 `docker-compose.yml` 的宿主机端口映射，或释放 3514 / 8514 / 5514 |
